# S7 — Hyperparameter Calibration via Genetic Algorithm

## Overview

S7 evolves the pipeline's hyperparameters with a Genetic Algorithm, **per chunking
strategy**, then returns the strategy + params that score highest. After the merge
two things changed:

1. the GA now tunes the **qentropy** parameters (most importantly the Tsallis `q`),
   and
2. its **fitness is the qentropy project's Table‑I evaluation** — the same signal
   used for the final ranking — instead of the old bespoke
   quality/coverage/consistency/efficiency reward.

## Genome (5 genes, normalised [0,1])

| gene | range | used by |
|------|-------|---------|
| `n_max` | 150…900 | S2 max words/chunk |
| `n_min` | 30…250 | S2 min words/chunk |
| `tau_sem` | 0.40…0.95 | S4 similarity‑merge threshold |
| **`q_entropy_param`** | **−1.0…1.0** | **S3 Tsallis q (drives `D_q` boundary count)** |
| `min_chunk_tokens` | 12…80 | S3 qentropy feasibility floor |

The dead JSD/percentile thresholds and the PPL‑calibration flag were removed, so
the whole evolutionary budget is spent on parameters that actually move the metric.

## Fitness = Table‑I evaluation

`pipeline/evaluation.py::ga_fitness` scores each individual's chunks:

- **With queries** (auto‑generated by `engine.qagen`): the primary P2 signal —
  **LLM answer‑correctness** when the judge is enabled, otherwise the
  **cosine‑rank mean** of MRR/NDCG/SRGT/QCS.
- **Offline** (no key, no queries): a label‑free coherence/separation/balance
  quality, so the GA still tunes `q` with zero external input.

A single `EvalContext` (query / ground‑truth / document embeddings) is built once
in `run_rl_loop` and reused across every individual of every generation — the same
embed‑once pattern the qentropy benchmark uses.

## GA mechanics (unchanged)

Tournament selection (k=3), BLX‑α crossover (α=0.5), Gaussian mutation
(rate 0.20, σ=0.15), elitism (2). Fitness is evaluated in the **main process**
(so the shared embedder + cached QA embeddings are reused); the S2→S3→S4 pipeline
for each individual runs in worker processes. Per‑strategy best params are
persisted to `rl_history.json` for warm‑starting future runs of the same domain.

If no individual beats the S2 baseline, the returned winner is re‑run once through
S2→S3→S4 so it always carries the qentropy annotations (`q`, `D_q`, …).

## Output

`run_rl_loop(text, doc_profile, initial_chunks, config) -> (best_chunks,
reward_history, final_config)` with `per_strategy_results` (best chunks, params,
fitness history). `main.py` then re‑scores every strategy's GA winner with the
full Table‑I metrics (`pipeline/evaluation.py`) and selects the overall winner via
the bootstrap‑CI + token‑cost policy — i.e. **the P2 metrics decide the result,
after the GA.**
